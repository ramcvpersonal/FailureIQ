💡 What is FailureIQ?

FailureIQ is a self-contained AI agentic system for automating root-cause analysis of application logs. You give it any log file and it returns a structured diagnosis: what broke, why, and the exact fix — including a code snippet.

It also serves as a teaching codebase demonstrating five core LLM engineering patterns in clean, readable Python.

📋
Input
Any log file: WAS SystemOut, heap dump, javacore, BVT regression, customer P1 case
🤖
Processing
ReAct agent: parse → RAG search → classify → LLM stream → validate
📊
Output
Structured JSON report: severity, root causes, immediate actions, code fix, prevention
🆓
Cost
Runs free locally with IBM Granite via Ollama. No API key needed.

🔁 The ReAct Agent Pattern — How It Thinks

ReAct = Reason + Act. Instead of sending the raw log straight to the LLM, the agent first uses deterministic tools to extract facts, then hands a rich, structured context to the LLM for reasoning. This makes the diagnosis far more accurate and traceable.

🧠
REASON
Agent reads the log and decides what to do next
⚙️
ACT
Calls a tool: parse_log, search_kb, or classify_severity
👁
OBSERVE
Tool runs and returns results (failures list, KB matches, severity)
📤
OUTPUT
LLM synthesises all observations into final JSON diagnosis

This is the same pattern used by LangChain Agents, AutoGPT, and IBM watsonx Orchestrate. The LLM never executes code directly — it only instructs. Python runs the tools and feeds results back.

⚡ Full Execution Pipeline (Step by Step)

Here is exactly what happens from the moment you run the command to the moment the report appears on screen.

1
User runs the CLI command
cli.py → main()
You type python src/cli.py --file logs/SystemOut.log. The CLI prints the banner, reads the file from disk using read_log_file(), and reports the file size.
2
LLM auto-detection
llm_client.py → LLMClient.create()
Makes a GET request to http://localhost:11434/v1/models. If Ollama responds, it picks the best installed model from a priority list (IBM Granite first). If Ollama is offline, it reads OPENAI_API_KEY from .env and uses GPT-4o. If neither works, it prints a clear install guide and exits.
3
Log type detection
tools.py → detect_log_type()
Reads the first 2,000 characters and looks for signature keywords. Returns one of: was_systemout (WebSphere logs), javacore (thread dump), heapdump (heap dump), bvt (Jenkins/Gradle), or generic.
4
Failure extraction
tools.py → parse_log()
Scans every line with a regex pattern that catches: FAIL, ERROR, Exception, FATAL, OutOfMemoryError, WSVR0605W, CWWKE0701E, SRVE0777E, heapdump, NullPointer, BUILD FAILURE, LEAK SUSPECT. For each match: deduplicates identical lines, extracts the test ID (e.g. [AUTH-004]), captures 5 lines of context below. Returns up to 15 failures.
5
RAG — Knowledge Base search
knowledge_base.py → search_knowledge_base()
For each failure: concatenates error_type + message + context and keyword-scores all 8 KB entries. Each KB entry has a list of trigger keywords; entries with the most keyword matches are returned. Top-3 matches per failure are stored as "ground truth" context for the LLM.
6
Rule-based severity classification
tools.py → classify_severity()
No LLM involved. Scans all error messages for hardcoded keyword tiers: CRITICAL if OOM / heapdump / server crash found; HIGH for hung threads / pool exhaustion / GC overhead; MEDIUM for 404 / timeouts / build failures; LOW otherwise.
7
Prompt assembly
agent.py → _build_context_message()
Builds a rich user message with: log type + severity header, up to 8,000 chars of log text (first 3,000 + last 5,000 for large files), formatted failure list, and all KB matches labelled as "ground truth". This is combined with a system prompt that tells the LLM it is an expert SRE and must return a specific JSON schema.
8
Streaming LLM call
llm_client.py → LLMClient.stream()
Calls the OpenAI chat completions API with stream=True. Tokens arrive one-by-one and are printed immediately — the same effect as ChatGPT's typing animation. Temperature = 0.2 (low randomness for factual analysis). Max tokens = 2,048. Works identically for Ollama (which uses the same API at localhost:11434) and OpenAI.
9
JSON extraction + Pydantic validation
agent.py → _parse_diagnosis() · schemas.py
Regex extracts the first {...} block from the streamed text. DiagnosisReport(**data) validates every field: types, ranges (confidence 0.0–1.0), required fields, and the severity enum. If the LLM returned malformed JSON, a safe fallback report is returned — the app never crashes.
10
Rich terminal report + optional JSON export
cli.py → _print_report()
Prints a colour-coded report using the rich library: severity badge, log type, failure count, root causes table with confidence %, immediate action list, and prevention recommendations. If --output report.json was passed, the full Pydantic model is serialised to disk.

🤖 LLM Provider — How Auto-Detection Works

FailureIQ uses the OpenAI Python SDK for both providers. Ollama exposes an OpenAI-compatible REST API at localhost:11434 — so we just point the same SDK at a different base URL. Zero code changes needed when switching providers.

The key insight: Ollama uses exactly the same OpenAI REST API format, just at a different base URL (http://localhost:11434/v1). This means zero code changes to switch between a free local model and a paid cloud model.

📐 Structured Output Schema

The LLM is instructed to return a strict JSON object. Pydantic validates every field — wrong type, missing field, or confidence outside 0.0–1.0 will be caught before the app uses the data. This makes LLM output reliable enough for production pipelines.

🚀 Quick Start — Step by Step

  • 1
    Install Ollama — the free local LLM runner
    Runs IBM Granite and Llama models entirely on your laptop. No API key. No internet after initial download.
    brew install ollama
ollama serve          # starts the Ollama API server on port 11434
  • 2
    Pull IBM Granite (recommended) or any Ollama model
    The agent auto-detects whichever model you have installed. IBM Granite is first in the priority list.
    ollama pull granite3.1-dense   # ~2 GB, IBM Granite — best for IBM demos
  • 3
    Install Python dependencies
    5 lightweight packages. Run from inside the FailureIQ/ folder.
    cd FailureIQ
pip install -r requirements.txt
  • 4
    Analyze any log file
    Pass any of the 7 included sample logs — or point it at your own log file.
    python src/cli.py --file logs/SystemOut.log
python src/cli.py --file logs/bvt-regression.log
python src/cli.py --file logs/heapdump.20240917.103000.AppServer01.0001.phd
python src/cli.py --file logs/javacore.20240917.103000.AppServer01.0002.txt
python src/cli.py --file /path/to/your/own/app.log
  • 5
    (Optional) Save the structured JSON report
    The full Pydantic model is serialised to JSON — pipe it into dashboards, Jira tickets, or Slack alerts.
    python src/cli.py --file logs/SystemOut.log --output report.json
  • 6
    (Optional) Run the full demo
    Runs all 5 sample log types back-to-back. Great for a live demo.
    python src/demo.py
  • 7
    (Alternative) Use OpenAI if Ollama is not available
    Copy the env template, add your OpenAI key, and run normally. The agent auto-detects the fallback.
    cp .env.example .env
# Edit .env → OPENAI_API_KEY=sk-...
python src/cli.py --file logs/SystemOut.log
